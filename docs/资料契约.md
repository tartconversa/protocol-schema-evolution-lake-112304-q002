# 资料契约

所有记录均为本地合成数据，使用 UTC 时间或 ISO 日期。标识字段用于关联文件，版次、状态、缺失、撤回和待审核值保留各自原始含义。

| 文件 | 字段 | 记录数 |
| --- | --- | ---: |
| `protocols.csv` | `protocol_id`, `version`, `lab_id`, `effective_from`, `review_state`, `parent_version` | 36 |
| `schema_fields.csv` | `protocol_id`, `version`, `field_id`, `name`, `type`, `unit`, `semantic_ref`, `required` | 80 |
| `run_results.csv` | `run_id`, `protocol_id`, `version`, `field_id`, `value`, `unit`, `recorded_at` | 160 |
| `mappings.csv` | `mapping_id`, `source_version`, `source_field`, `target_version`, `target_field`, `transform_note`, `approval_state` | 60 |

缺失值、争议状态、部分成功和待复核均不表示零值或已完成。原始值不预置分析结论，转换依据及研究解释须由应用能力提供。

## 资料中的刻意瑕疵

这些瑕疵用于检验能力是否保守，装载器不会静默修正：

* `protocols.csv` 每条方案记录重复三次（内容相同），去重后为 12 条方案版本；
* `schema_fields.csv` 中 32 个字段键各含两行，物理定义相同但 `semantic_ref` /
  `required` 冲突，装载后标记为 `disputed`；
* 同一 `type` 在不同实验室不同（`int` / `float` / `string`），数值以十进制文本记录，
  53 条声明为 `int` 的记录含小数，53 条声明为 `string` 的记录可解析为数值；
* `mappings.csv` 每个映射键有 3–4 条重复记录，审批状态互相冲突；转换说明与物理定义
  普遍矛盾（`same` 两端单位不同、`split` 只有一个目标、`unit-convert` 两端字段名不同）；
* 9 个协议族的当前版本引用了本族未登记的父版本。

因此在本资料上**没有任何指标可跨版本合并**，每个字段都以 `version_only` 输出并附原因。
可用正例参见 `fixtures/coherent/`（提供语义评审与单位换算）与
`fixtures/adjudicated/`（提供治理裁定）。

## 可选治理文件

除上述四个契约文件外，应用能力可读取以下治理文件（均使用 `utf-8-sig`、`\n` 换行）：

| 文件 | 字段 |
| --- | --- |
| `semantic_reviews.csv` | `review_id`, `source_version`, `source_field`, `target_version`, `target_field`, `judgment`, `basis`, `reviewer_role`, `decided_by`, `decided_at`, `review_state` |
| `unit_conversions.csv` | `conversion_id`, `source_unit`, `target_unit`, `factor`, `offset`, `approval_state`, `approved_by`, `basis` |
| `mapping_adjudications.csv` | `adjudication_id`, `source_version`, `source_field`, `target_version`, `target_field`, `effective_state`, `effective_note`, `basis`, `decided_by`, `decided_at` |

受控词表与判定规则见 `docs/使用说明.md`。
